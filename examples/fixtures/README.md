# Synthetic fixtures

Every file here is **synthetic**. There is no real customer, billing, account,
or PII data. The data is generated by a seeded standard-library script so anyone
can reproduce it bit-for-bit:

```bash
python3 scripts/generate_fixtures.py
```

Seed: `1111`. Rows per file: `500`. Re-running the script overwrites these CSVs
with identical content.

## Baseline

`orders_baseline.csv` is a stable synthetic orders table with this schema:

| column | type | notes |
|---|---|---|
| `order_id` | string | unique, `ORD-100000`+ |
| `customer_id` | string | high cardinality, ~300 distinct of 500 |
| `product_sku` | string | one of 40 SKUs |
| `quantity` | int | 1 to 12 |
| `unit_price` | float | 5.00 to 500.00 |
| `revenue_usd` | float | `quantity * unit_price` |
| `currency` | string | mostly USD |
| `status` | string | paid / pending / refunded / cancelled |
| `region` | string | AMER / EMEA / APAC / LATAM, ~2% null |
| `created_at` | string | ISO-8601 timestamp |

`region` deliberately avoids the code `NA`, which a data-quality profiler
correctly reads as a null token. Using it as a category value would be
ambiguous by design.

## Drift scenarios

Each scenario is the baseline with exactly one controlled failure injected. The
nightly cron rotates which scenario it scans by date (`day.toordinal() % 5`), so
the public dashboard genuinely detects a different drift each day.

| file | injected drift | expected finding | severity |
|---|---|---|---|
| `orders_drift_schema_add.csv` | adds a `discount_code` column | `schema_add` | low (pass) |
| `orders_drift_null_rate.csv` | blanks `region` in ~40% of rows | `null_rate_shift` | high (fail) |
| `orders_drift_value_distribution.csv` | scales `revenue_usd` toward zero in ~95% of rows | `distribution_shift` | critical (fail) |
| `orders_drift_cardinality_collapse.csv` | remaps `customer_id` onto 15 distinct values | `cardinality_collapse` | critical (fail) |
| `orders_drift_type_coercion.csv` | turns `quantity` into free text in ~60% of rows | `type_change` | high (fail) |

## Detection thresholds

These are the thresholds in `src/data_quality_watchtower/comparator.py`. Any
third party can change a fixture, re-run the scan, and see the verdict move:

- Null-rate shift: absolute change >= 0.15 (>= 0.30 escalates to high).
- Distribution shift: relative mean change >= 0.30 (>= 0.50 high, >= 0.80 critical).
- Cardinality collapse: current/baseline distinct <= 0.50 on a column whose
  baseline had >= 20 distinct values (<= 0.25 escalates to critical).
- Schema remove and type change: high. Schema add: low.

A run fails the gate when the worst finding is `high` or `critical`.
